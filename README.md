# Томедия: первая локальная афиша

Node.js 22+; сторонние npm-зависимости не требуются.

## Локальный запуск

Из этой папки выполните `npm start`. Откройте http://localhost:3000.
Если .env отсутствует, скопируйте .env.example в .env и задайте два ключа:
- QTICKETS_TOKEN — REST API (афиша);
- QTICKETS_PARTNERS_TOKEN — partners API (схема зала и цены мест).

Настоящие ключи уже добавлены в локальный .env. Не отправляйте их в Git, архивы или публичные файлы.

## Работа

Афиша: сервер читает только GET /shows и GET /events QTickets REST API.
Схема зала: GET /api/seatmap/{мероприятие}-{сеанс} читает events/seatmap и events/offers partners API — только для сеансов, которые сейчас есть в афише. Ответ кешируется на 30 секунд на сеанс (ошибка — на 10 секунд), поэтому частые нажатия не расходуют лимиты QTickets. Выбор мест на сайте ничего не бронирует.
В запросе /shows задаёт фильтры is_active=1, deleted_at=null и start_date>=текущего момента. Затем запрашивает только активные неудалённые мероприятия по ID этих сеансов. Архив не загружается; пагинация применяется только к отфильтрованным результатам, по 100 записей на страницу. Время на сайте отображается по Томску.
Обновление — по запросу, не чаще раза в пять минут. При сбое после успешной загрузки остаётся предыдущая афиша с предупреждением.
В браузер возвращается только публичная выборка полей; заказы и покупатели не запрашиваются.
Изображение берётся из poster.url (http-адреса переводятся на https). Кнопка покупки использует url из QTickets, с резервным site_url. Если адрес не задан, ссылка не выдумывается.
Цены — минимальные default_price сеанса, а не гарантия доступности билетов по этой цене.

## Передача админу

Передать все файлы кроме .env. Оба ключа (QTICKETS_TOKEN и QTICKETS_PARTNERS_TOKEN) сообщить отдельно.
Создать .env на VPS и выполнить `docker compose up -d --build`.
Сервис доступен только на 127.0.0.1:3000; снаружи его публикует nginx/Caddy с HTTPS.
Для тестовой версии использовать отдельный поддомен с паролем; действующий сайт не переключать.
